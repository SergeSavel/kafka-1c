# Подсистема взаимодействия с Apache Kafka через HTTP-шлюз

Мини-фреймворк для построения обменов 1С:Предприятие 8.3 с Apache Kafka.

Подсистема снимает с разработчика низкоуровневое взаимодействие с Kafka — но не закрывает к нему доступ: когда
задача выходит за рамки типового обмена, весь набор операций отправителя, получателя и администратора остаётся под
рукой.

Подсистема встраивается в основную конфигурацию, не пересекается с ней по метаданным и не имеет внешних зависимостей —
в том числе от БСП. Это база для построения индивидуальных обменов, не предназначенная для модификации: конкретные
обмены надстраиваются над ней, например в расширениях конфигурации, поэтому обновление подсистемы не затрагивает
ваши доработки. Подсистема поставляется как конфигурация поставщика и ставится на поддержку — открытыми остаются
только точка расширения и сама подсистема «Кафка», чтобы в неё можно было добавлять вложенные.

Внутри — автоматизация отправки и получения данных и графический интерфейс администрирования кластера Kafka.
Фактически разработчик реализует только две вещи:

- логику регистрации данных к обмену и формат отправляемых данных — XML, JSON, что угодно;
- логику записи получаемых данных в информационную базу.

Остальное настраивается через графический интерфейс, без участия разработчика.

## Возможности

Обмен в обе стороны идёт по расписанию и в несколько потоков, ход обмена и ошибки фиксируются в журнале регистрации.
Копия рабочей базы, развёрнутая для тестов, не отправит данные в рабочий контур: обмен в ней либо блокируется, либо
автоматически переключается на тестовые темы.

### Отправка данных в Kafka

**Ничего не теряется.** Данные к отправке регистрируются штатными средствами платформы: отправленное снимается с
регистрации, неотправленное дожидается следующего сеанса.

**Правильный порядок.** Очерёдность выгрузки задаётся прикладными правилами: справочники уходят раньше документов,
зависимые данные — после того, от чего они зависят.

**Скорость.** Данные отправляются параллельно, число потоков настраивается для каждого обмена.

**Формат сообщения — ваш.** Ключ и значение формирует прикладной код: JSON, XML, строка, UUID или двоичные
данные. Сообщения одного обмена можно разносить по разным темам — например, по видам объектов.

### Получение данных из Kafka

**Приём в прикладной код.** Каждое сообщение передаётся процедуре конфигурации: она сама решает, что создать,
обновить или проигнорировать.

**Одна тема или группа тем.** Читать можно как конкретную тему, так и все подходящие по шаблону имени.

**Чтение в несколько потоков.** Скорость приёма растёт вместе с числом разделов темы.

**Реальное время.** Обмен может работать сеансами заданной длительности, забирая сообщения сразу по мере появления, —
когда данные нужны не «раз в час по расписанию», а немедленно.

**Надёжное чтение.** Позиции чтения подсистема ведёт самостоятельно и фиксирует только после того, как данные приняты
базой: сообщения не теряются при обрыве связи и не читаются повторно после перезапуска.

### Администрирование Kafka из 1С

**Рабочее место администратора.** Состояние кластера и брокеров, создание и удаление тем, разделы и конфигурации,
группы получателей с участниками и смещениями, пользователи SCRAM и права доступа ACL — отдельный инструмент для
администрирования Kafka не нужен.

**Управление позициями.** Позиции чтения видны и доступны для правки: обмен можно перечитать с нужного места или
перемотать вперёд.

**Разграничение доступа.** Рабочее место открывается по отдельной роли, подключение к Kafka поддерживает TLS и
аутентификацию SASL — PLAIN, SCRAM-SHA-256 и SCRAM-SHA-512.

### Прямая работа с Kafka из кода

Возможности не ограничены обменом по расписанию: прикладной код может обращаться к Kafka напрямую, с теми же
настройками подключения. Доступны отправка и чтение отдельных сообщений, транзакции, подписка на темы, перемотка к
нужной позиции и административные операции, а также готовые функции сериализации JSON и XML. Разовый сценарий —
отправить сообщение по событию или прочитать ответ из служебной темы — не требует настройки обмена.

## Как это устроено

```
1С:Предприятие  ──HTTP──▶  Kafka HTTP Gateway  ──▶  Apache Kafka
```

Работу с брокерами берёт на себя Kafka HTTP Gateway — лёгкий сервис,
который ставится рядом и общается с 1С по HTTP. Сетевой доступ к Kafka нужен только ему; на стороне 1С не требуется
ни внешних компонент, ни особых прав.

## Требования

- 1С:Предприятие 8.3.10 или новее, управляемое приложение;
- развёрнутый Kafka HTTP Gateway и доступный ему кластер Apache Kafka.

## Установка и настройка

Скачайте поставляемый CF со страницы релизов проекта и загрузите его в информационную базу. Рядом понадобится Kafka HTTP Gateway той же версии — ссылки на релизы обоих компонентов собраны в [документации](docs/index.md).

Дальше — три шага в пользовательском режиме:

1. **Кластер** — подключение к шлюзу и к Kafka.
2. **Шина** — маршрут обмена: кластер, тема, направление, форматы ключа и значения, потоки и расписание.
3. **Обработка обмена** — обработка конфигурации, которая готовит данные к отправке или принимает полученные.
